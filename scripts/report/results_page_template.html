Main findings

Most methods were run on one fixed set of 1,000 plans from the RPLAN test split, so their numbers compare directly. "Real" always means the same metric computed on real plans.

  • Boundary-conditioned methods produce the cleanest geometry. WallPlan breaks a rule in 12% of plans, against 17% for real RPLAN plans, and has the closest image distribution after DiffPlanner (FID 3.2 against its own GT). iPLAN follows (FID 5.7).
  • DiffPlanner looks the most realistic as images (FID 0.7) but produces many too-narrow rooms. 8.4% of its rooms are below the minimum width, against 2.7% in real plans, so 46% of its plans break a rule. Its FID is also not directly comparable: it ran on all 12k test plans, the same set as the reference.
  • MaskPLAN is clearly the weakest boundary method. It produces 5.1 rooms per plan instead of 6.8 and lets the living room absorb the rest (FID 47).
  • A boundary alone doesn't determine one layout. Every boundary method recovers the GT room layout only partly (per-type IoU 0.38–0.46, MaskPLAN boundary-only 0.28). These paired scores measure how close a method gets to one real plan, not plan quality.
  • Of the bubble-diagram methods, GSDiff matches the input graph best and looks most realistic. Adjacency F1 0.90, FID 15.0. HouseDiffusion always gets room counts and types right (it draws one polygon per input node) at FID 18.7. House-GAN++ hides rooms under later rooms, so only 52% of plans have the right room count.
  • House-GAN rooms overlap heavily. On average the rooms' summed area exceeds the plan footprint by 24%, so every plan breaks the overlap rule.
  • The LLM-based DS2D is close to real on ProcTHOR but weak on RPLAN. On ProcTHOR its FID is 3.3–4.7, against a real-data floor of 2.1, and it gets room adjacency right (F1 0.91–0.94). On RPLAN its FID is 32–41, rooms overlap by 3–8%, and the 5-room model almost always draws 8 rooms.
  • ChatHouseDiffusion (text input) is at the image-realism noise floor (FID 2.3, real-data floor 2.9). It produces twice the real share of too-narrow rooms (14% vs 6%).

How the scores are computed

Every method's output and every dataset is first converted to one JSON format (room polygons with a canonical type, optional boundary, doors and room graph). All lengths are in meters. A gap of up to 0.6 m between rooms counts as a wall.

Overlap
How much the summed room area exceeds the plan footprint, relative to the footprint.
Holes
Enclosed space wider than a wall that belongs to no room.
Boundary covered
Share of the input outline filled by rooms.
Pieces
Connected components of the room adjacency graph. A plan should be 1 piece.
Too small / narrow / elongated
Rooms below a minimum area or clear width, or above a maximum aspect ratio, for their room type. For example, bedrooms need at least 5 m² and 2.0 m width.
Room count / types right
Same number of rooms, or the same multiset of room types, as the GT plan for that input.
Adjacency F1
Overlap between the sets of touching room-type pairs (e.g. living–bedroom) of the generated and GT plans.
Type mIoU
Per-type pixel overlap with the GT plan. Only for methods that receive the boundary, since only those share the GT frame.
FID / KID
Image distance between rooms-only renders of the generated and real sets. "Against own GT" uses the GT plans for the same inputs, so sample size and input distribution match.

Limits of this round

  • Test inputs come from Graph2Plan's copy of RPLAN. The original RPLAN images need a request form. Without them, the papers' own test splits for House-GAN++, HouseDiffusion and GSDiff can't be reproduced. The interior doors that House-GAN++ and HouseDiffusion take as input had to be made up.
  • FID depends on sample size. Compare the "against own GT" column within one dataset. KID is more reliable for the 500-plan sets.
  • Raster outputs are vectorized. House-GAN, House-GAN++, MaskPLAN and ChatHouseDiffusion produce pixel masks. The current converters cut staircase corners into slanted edges, so their rectilinearity isn't reported.
  • Merged room types. GSDiff merges study into bedroom and dining into living room, which lowers its type scores by design.
  • Not yet run. Residential Floorplan Diffusion (weights need Google Drive access approval from the authors) and Floor-plan RLVR (a 70B model that needs all four GPUs).

Decisions needed

  1. Rule thresholds. The minimum areas, widths and aspect ratios are loose defaults. Should they follow a specific building norm or region?
  2. Request the original RPLAN data through its form, to reproduce the official test splits.
  3. Run Floor-plan RLVR (70B), which needs all four GPUs, or skip it.
  4. House-GAN's LIFULL data comes with a non-commercial license that forbids redistribution. We use it locally only. Is that acceptable?

Planned next

  • One pixel-exact converter for all raster outputs, so rectilinearity applies to every method.
  • Door-based metrics: can every room be reached from the entrance.
  • MaskPLAN on the same 1,000 test plans as the other methods.
