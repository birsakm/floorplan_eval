# All methods side by side

Generated by `scripts/report/compare_methods.py`. Rules and input adherence: `python -m fpeval.evaluate variants` (docs/metrics.md §1–2). FID/KID: every plan rendered by `fpeval.render.render_layout` (256 px, type colours, 4 px walls, no doors or windows; docs/metrics.md §5), Inception-V3 features, KID ×1000.

How to read FID/KID: each row is scored against real plans of its own dataset, and the **floor** is the score of real plans at the same sample size against the same reference: for methods with paired inputs, the GT plans of exactly those inputs (what reproducing the GT would score); for our plans, held-out composition-matched real plans; otherwise random real plans. FID depends strongly on N (biased upwards at small N), so compare **FID − floor** and KID across rows with different N; KID is unbiased. Rows with different references measure different things and are not a ranking. None of these numbers are comparable with the numbers printed in the papers, which use their own renderers and sample counts.

Columns: N generated plans scored (random subset of at most 1,000); rule = plans breaking a basic rule (overlap, holes, pieces, minimum area/width, maximum aspect); types = plans whose room types and counts equal the input (paired methods: the GT plan; ours: the brief).
